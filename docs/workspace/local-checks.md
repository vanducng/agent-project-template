# Local checks: browser, screenshots, throwaway state

The rule table in the workspace root `AGENTS.md` lists each rule and the check that enforces it; this page keeps the full text.

- Browser checks use Aside, not ego (product owner, 2026-10-19): drive it with `aside repl` (run `aside guide repl` first) for UI checks and screenshots. A check opens its own tab with `openTab()` and closes it with `closeTab()` the moment the check is done, reuses that one tab across rounds instead of opening more, and never uses `page.context().newPage()` or `page.close()` (they leak renderers). Close any tab of your own left from an earlier item before starting, and leave the product owner's tabs alone. Background browser renderers run only on the Mac's four efficiency cores, so forgotten tabs pin them and stall every seat on the machine.
- Screenshots that show personal data (names, emails, phones, client or staff identifiers) redact it with a white blur: a heavy blur over the area plus a white fill, so nothing is readable and the shot stays light and clean. Never black boxes (operator, 2026-10-31). Check the redacted file at full size before it goes into a pull request, ticket, message or proof; keep any unredacted original only in the capture's internal folder, never in git.
- Throwaway state dies with the run that made it (operator, 2026-11-05). A test, gate, capture or probe that starts a container removes it with `docker rm -fv` or `docker compose down -v` in its exit trap, so no anonymous volume, network or temp database outlives the run; a throwaway database keeps its data dir on `--tmpfs` when the run allows it. Scratch output goes under the task dir or a `.cache/`, never a stray `/tmp` pile. A worktree's named volumes, buckets and databases go at its cleanup gate. A run that leaves state behind is a defect: fix the script in the slice, and the reviewer treats a new `docker run` or compose stack without that cleanup as a defect.
